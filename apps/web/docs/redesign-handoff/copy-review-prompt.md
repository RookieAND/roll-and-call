# Claude Design 문구 감수 요청문 (붙여넣기용)

---

당신은 모바일 웹앱 **롤앤콜**(TRPG 세션 모집·일정 조율 서비스)의 한국어 UX 라이터입니다. 이번 작업은 디자인 수정이 아니라 **시안에 적힌 문구만** 보는 감수입니다. 레이아웃, 컴포넌트, 색, 간격은 건드리지 마세요.

## 목표

시안 문구 중 **한국어 사용자가 읽었을 때 어색하거나, 화면끼리 규칙이 어긋나는 곳**을 찾아 원문 → 제안 형태로 정리해 주세요. 뜻과 기능은 그대로 둡니다. 문장이 짧아지는 건 환영이지만, 정보가 빠지면 안 됩니다.

## 대상

프로젝트의 `리디자인 01 ~ 11` 시안 파일 전부. 화면에 보이는 모든 글자가 대상입니다.

- 앱바·탭·섹션 제목
- 버튼·칩·배지 라벨
- 입력 라벨, 플레이스홀더, 도움말, 검증 에러
- 토스트, 다이얼로그, 시트, 툴팁
- 빈 상태·로딩·에러·권한 없음 문구
- 날짜·인원·순번 같은 데이터 표기(`{ }` 자리 포함)

## 무엇을 "어색하다"고 볼지

아래 범주 코드를 제안마다 붙여 주세요. 감이 아니라 범주로 지적해야 합니다.

| 코드 | 범주 | 설명 |
|---|---|---|
| A1 | 어미 혼용 | 한 화면, 한 종류의 문구 안에서 `~습니다` / `~해요` / 명사형 종결이 섞임 |
| A2 | 구두점 혼용 | 같은 종류인데 마침표가 있다 없다 함. 실제 예: "가능 시간대를 저장했습니다"(무) vs "가능 시간을 저장하지 못했습니다."(유) |
| B1 | 불필요한 피동 | 주체가 분명한데 피동으로 씀. 실제 예: "구인이 등록되었습니다" ↔ 같은 앱의 "메모를 저장했습니다". 또 "대기로 접수됐습니다"와 "대기로 접수했습니다"가 둘 다 있음 |
| B2 | 무생물 주어 | 영어식으로 사물이 행동하는 문장 |
| C1 | 번역투 상투구 | "문제가 발생했습니다", "~하실 수 있습니다", "확인 부탁드립니다" 류 |
| C2 | 군더더기 | "~하는 것이 가능합니다", "~에 대하여", 빼도 뜻이 같은 부사·수식 |
| D1 | 명사 나열 | 관형어가 줄줄이 붙는 한자어 뭉치("모집 마감 기한 설정 변경" 류). 조사를 넣거나 동사로 풀기 |
| D2 | 불필요한 대명사 | "당신의", "귀하의", 굳이 넣은 "나의" |
| E1 | 용어 불일치 | 같은 개념을 화면마다 다르게 부름. 특히 브리프의 "마감" 두 뜻, GM 표기, 참여/대기/확정 |
| E2 | 라벨 형태 불일치 | 버튼이 어디선 동사구("참여하기"), 어디선 명사("참여")로 나옴 |
| F1 | 길이 | 412px에서 두 줄 이상 흐르는 버튼·칩 라벨, 토스트 |
| F2 | 책임 소재 | 에러 문구가 사용자를 탓하거나, 반대로 무엇을 해야 할지 안 알려 줌 |

## 기준선으로 삼을 것

이 서비스의 현재 문구는 **짧고 입말에 가까운 쪽**이 기준입니다. 좋은 예와 나쁜 예를 실제 문구에서 뽑으면 이렇습니다.

- 좋음: "빈 자리는 저절로 차지 않습니다. 대기에서 직접 확정시키세요." / "뽑은 뒤에도 명단은 고칠 수 있습니다." / "기한까지 모아 GM이 뽑습니다."
- 고칠 것: "문제가 발생했습니다"(C1) / "구인이 등록되었습니다"(B1) / "모집이 마감되었습니다."(B1)

새 문구를 쓸 때도 이 결을 따라 주세요. 한자어보다 쉬운 말, 설명보다 동사, 두 문장이면 각각 짧게.

## 산출물

**1. 감수 표** — 화면 순서대로, 한 행에 하나씩.

| 화면 | 위치 | 원문 | 제안 | 코드 | 심각도 |
|---|---|---|---|---|---|

- 위치는 "구인 상세 · 하단 액션 바 · 참여 버튼"처럼 찾아갈 수 있게 적어 주세요.
- 심각도: High(뜻이 헷갈림·용어 충돌) / Med(어색함·규칙 어긋남) / Low(취향).
- **원문은 한 글자도 바꾸지 말고 그대로** 옮겨 주세요. 대조가 이 작업의 전부입니다.

**2. 규칙으로 승격할 것** — 표에서 같은 지적이 세 번 넘게 반복되면 개별 행 대신 규칙 한 줄로 묶고, 해당 화면 목록만 다세요. 예: "토스트는 마침표 없음 — 적용 화면 04, 06, 07, 11".

**3. 보이스 가이드 초안** — 감수하며 실제로 쓴 판단 기준을 10~15줄로 정리해 주세요. 이건 저장소 문서로 들어갑니다. 항목마다 한 줄 규칙 + 좋은 예/나쁜 예 한 쌍.

**4. 판단 보류 목록** — 도메인 지식이 있어야 고칠 수 있는 것(어느 쪽이 맞는 용어인지 등)은 고치지 말고 질문으로 남겨 주세요.

## 제약

- **시안 파일을 수정하지 마세요.** 이번 회차는 표와 문서만 냅니다. 반영 여부는 제가 정한 뒤 다음 요청으로 드립니다.
- 문구의 **뜻·조건·숫자·권한 설명을 바꾸지 마세요.** 짧게 줄이다가 조건이 빠지면 그건 버그입니다.
- 기능을 새로 제안하지 마세요. 문구로는 해결이 안 되는 문제를 찾으면 "문구 밖 문제"로 따로 적어 주세요.
- 브리프(`brief.md`)의 용어 정의를 정답으로 보세요. 브리프와 시안 문구가 다르면 그 자체가 High 지적입니다.

## 작업 순서

1. 시안 전체를 훑어 **문구 목록을 먼저 뽑고**, 종류별(버튼/토스트/에러/빈 상태/도움말)로 모아 주세요. 화면 단위보다 종류 단위로 봐야 규칙 어긋남이 보입니다.
2. 종류별로 규칙을 정한 뒤, 그 규칙에 어긋나는 것을 표로 내려주세요.
3. 마지막에 보이스 가이드 초안.

1단계가 끝나면 종류별 문구 개수와 눈에 띈 규칙 후보를 짧게 먼저 알려 주세요. 거기서 방향을 맞추고 2단계로 갑니다.
