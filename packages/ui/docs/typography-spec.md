# 타이포그래피 · `Text` 재정의 스펙

리디자인 시안에 **타이포 스케일이 정의돼 있지 않아서** 생긴 드리프트를 닫기 위한 의뢰서다.
핸드오프 README의 "디자인 토큰 실측표"는 색과 폼 치수만 담고 있고, 글씨는 `Field 라벨 12.5px/700` 한 줄이 전부다.
시안 파일은 인라인 스타일로 그려져 있어 크기가 그때그때 박혀 있다.

이 문서는 **시안 쪽이 채워 줄 것**과 **채워지면 코드가 할 일**을 함께 적는다.

## 3. 결함 넷

### D1. 크기와 굵기가 한 축에 묶여 있다

`subtitle1`은 14/700, `body2`는 14/400이다. 같은 크기인데 이름이 다르고, **빠진 조합은 만들 방법이 없다.**
13px 굵게가 필요하면 `typography="body3" className="font-bold"`가 되고, 실제로 4곳이 그렇다.
12px 세미볼드도 마찬가지로 6곳이다. 굵기 덮어쓰기 14곳은 전부 `body3`·`body4`에 몰려 있다.

### D2. 스케일에 구멍이 있다

가장 큰 구멍은 **12.5px 26곳**이다. `body4`(12)와 `body3`(13) 사이에 있고, 시안이 본문으로 쓰는 크기다.
그 다음이 11.5px 6곳(캡션), 19·17·15px(제목 단계 사이).

### D3. 프리미티브가 자기 스케일을 안 쓴다

`Field` 라벨, `Chip` pill, `SegmentControl` 라벨이 `text-[12.5px]`를 직접 박는다.
`Text` 스케일에 12.5px이 없기 때문이다. `packages/ui` 안에만 크기 하드코딩이 18곳이다.

### D4. 기본 엘리먼트가 문단이 아니다

`Text`는 `<span>`으로 렌더한다. 실제로는 96곳이 `render={<p />}`를 달고, 40곳이 `className="block"`을 더한다.

### 4.2 산출물 형식

각 단계마다 이 여섯 칸을 채워 주면 그대로 코드가 된다.

| 이름 | px  | line-height | weight | letter-spacing | 쓰는 자리 (화면 예 1개) |
| ---- | --- | ----------- | ------ | -------------- | ----------------------- |

조건:

- **이름은 역할로 짓는다.** `body4`는 크기도 역할도 말해 주지 않는다. `caption` `label` `body` `title`처럼 어디에 쓰는지가 이름에 있어야 한다.
- **라이트·다크가 같은 값인지** 명시한다(색만 뒤집히고 크기는 같다면 그렇게 적어 주면 된다).
- **본문으로 쓰는 단계는 대비 4.5:1**을 넘겨야 한다. 보조 문구는 `hint` 토큰이 이미 그 선에 맞춰져 있다.
- 단계는 **7개 안팎**이 적당하다. 지금 12개 중 3개가 사용 0이고, 실측 클러스터도 7개다.

## 5. 코드가 할 일 (결정 뒤)

### 5.1 `Text` API 제안

굵기를 뗀다면(Q4 = 예):

```tsx
<Text size="body" weight="bold" foreground="muted" />
```

떼지 않는다면 지금 형태를 유지하되 빠진 조합을 변형으로 채운다.

그와 별개로 반복되는 셋은 prop으로 올린다 — 셋 다 순수하게 반복 제거라 결정과 무관하게 진행할 수 있다.

| prop                    | 하는 일               | 지금                               |
| ----------------------- | --------------------- | ---------------------------------- |
| `numeric`               | `tabular-nums`        | className 24곳                     |
| `truncate`              | `block truncate`      | className 20곳 + `block` 40곳 일부 |
| 기본 엘리먼트를 `<p>`로 | `render={<p />}` 제거 | 96곳 제거 / `<span>` 46곳 추가     |

기본 엘리먼트 교체는 96곳이 줄고 46곳이 느는 맞교환이다. 순이득 50곳.

### 5.2 프리미티브 정리

`Field` · `Chip` · `SegmentControl` · `Button` 이 `Text`의 스케일을 참조하도록 바꾼다. 지금은 각자 px를 박는다.

### 5.3 수용 기준

- `apps/web/src`의 글씨 크기 하드코딩 **0곳** (지금 81)
- `<Text>` 중 `className`으로 크기·굵기를 덮는 것 **0곳** (지금 30)
- `packages/ui` 안의 크기 하드코딩 **0곳** (지금 18)
- `pnpm lint:tokens`에 글씨 크기 검사를 더해 다시 새지 않게 막는다

## 6. 다음 범위 (이번엔 아님)

타이포가 닫히면 같은 방식으로 이어서 볼 것들. 각각 실측부터 한다.

- **간격** — `gap` 토큰은 있는데 `mt-[3px]` `py-[5px]` 같은 임의값이 섞여 있다
- **radius** — `rounded-[14px]` `rounded-[10px]` `rounded-[7px]`가 토큰 없이 돌아다닌다
- **높이** — 버튼 h-11 / h-[46px] / h-[50px]이 자리마다 다르다
- **아이콘 크기** — `size={14}` `size={15}` `size={16}`이 규칙 없이 섞인다
