# 패치노트 발행

## 데이터

- `notes.json` — 지금까지 발행한 모든 패치노트. 발행 후 `message_id`가 기록되므로
  **이 파일이 곧 발행 대장이다.** 절대 항목을 지우지 말 것.
- 웹훅 주소는 `apps/web/.env.local`의 `DISCORD_PATCHNOTE_WEBHOOK_URL`에서 읽는다.

## 새 패치노트를 발행할 때

1. `notes.json`의 마지막 항목 `date`를 확인하고, 그 이후 커밋만 본다:
   `git log --since=<마지막 날짜> --date=short --pretty='%ad|%s'`
2. **사용자에게 보이는 변화만** 남긴다. 리팩터링·구조 개편·마이그레이션·포매팅·
   의존성 업데이트·문서 수정은 전부 뺀다. 커밋 메시지를 그대로 옮기지 말고,
   그 변경이 유저 화면에서 무엇을 바꾸는지로 다시 쓴다.
3. 날짜별로 묶어 `notes.json` 끝에 항목을 추가한다. `message_id`는 넣지 않는다.

   ```json
   {
     "version": "v0.9",
     "date": "2026-09-27",
     "emoji": "🎯",
     "title": "3~5 단어 주제",
     "intro": "이번 패치에서 해결하려던 문제 한 문장.",
     "groups": [
       ["✨ 새로 생긴 것", ["항목", "항목"]],
       ["🐞 고친 것", ["항목"]]
     ]
   }
   ```

   - `version` — 직전 항목에서 minor를 1 올린다. 릴리스 태그가 생기면 그걸 따른다.
   - `intro` — **기능 나열이 아니라 문제 서술.** "무엇이 불편했는지"로 시작한다.
   - `groups` — `✨ 새로 생긴 것` / `🎨 다듬은 것` / `🐞 고친 것` 중 해당하는 것만.
     순서는 이 순서를 지키되, 그 패치의 핵심이 든 묶음을 맨 앞에 둬도 된다.
   - 항목 중 핵심 하나는 `**굵게**`로 강조한다. 한 줄은 한 문장을 넘기지 않는다.

4. `python3 .claude/skills/patch-notes/post.py` 실행. 새 항목만 전송되고
   받은 `message_id`가 `notes.json`에 기록된다.

## 이미 올린 패치노트를 고칠 때

`notes.json`에서 해당 항목만 고치고 같은 명령을 다시 돌린다. `message_id`가 있는
항목은 새로 보내지 않고 그 메시지를 수정하므로 채널에 중복이 쌓이지 않는다.

## 규칙

- 임베드 field는 `inline: false`로 둔다. 항목 문장이 길어 2열로 만들면 줄바꿈이 깨진다.
- 발행은 되돌릴 수 없다. 보내기 전에 유저에게 임베드 내용을 먼저 보여주고 확인받는다.
